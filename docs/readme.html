會議室預約系統

一套給約 200 人組織使用的會議室預約系統。它和一般預約系統最大的差別是：每位成員有優先等級，較高等級可以覆蓋較低等級已經訂走的時段。

這套系統在做什麼

成員登入後可以看到所有會議室的當日狀況，選一個空的時段預約。如果那個時段已經有人，而你的等級比對方高，系統會問你要不要覆蓋——覆蓋不是靜悄悄發生的，一定要你親自確認。

  • 成員：註冊 → 等管理員審核 → 瀏覽空檔 → 預約 → 收到確認信 → 會議前收到提醒信
  • 管理員：審核註冊 → 發送邀請 → 調整成員等級 → 管理會議室 → 調整規則 → 查看覆蓋紀錄

預約紀錄永遠不會被刪除

取消或被覆蓋的預約只會改變狀態，資料永久保留。你隨時可以在「我的預約」看到自己曾經被覆蓋過哪些時段、以及原因。

管理員身分不等於高優先權

管理員可以管理系統，但在搶會議室這件事上和大家一樣——決定誰能覆蓋誰的，只有等級數字。一位等級 3 的管理員無法覆蓋等級 5 的一般成員。

帳號的一生

有兩條路可以成為正式成員。自行註冊要經過驗證與審核；由管理員發出邀請則一步到位。

註冊頁面不會告訴你某個信箱是否已經註冊過

無論輸入的信箱是新的還是已存在，畫面都顯示同一句「請至信箱查收」。這是為了避免有人拿註冊頁面來試探公司裡有誰。已存在的信箱會收到一封「你已經有帳號了」的通知信。

我的帳號

上方選單的「帳號」是每個人管理自己資料的地方：變更密碼，以及刪除帳號。

介面語言

右上角的地球圖示點一下會展開語言選單，可以在 English 與繁體中文之間切換。預設是 English；選過之後系統會記住，換裝置登入也會沿用，會議提醒信也會用同一種語言寄出。

刪除帳號

成員可以自己刪除帳號，管理員也可以刪除任何人的帳號。刪除是無法復原的，所以自己刪除時必須輸入一次密碼，管理員刪除別人時會先看到一頁確認畫面。

刪除帳號，但不刪除紀錄

帳號刪除後會立刻登出，未來的預約會一併取消，會議室馬上釋放給其他人。過去的預約、覆蓋紀錄與稽核紀錄全部保留，但其中的姓名、電子郵件與電話會被移除，在管理後台顯示為「已刪除的成員」。原本的電子郵件位址會被釋放，同一個人日後可以再重新註冊。

系統上最後一位管理員無法被刪除

沒有管理員的系統無法審核新成員、無法修改設定，也沒有任何畫面可以把管理員加回來。要刪除最後一位管理員，請先把管理權限給另一個人。

預約規則

送出預約時，系統會依固定順序檢查以下條件，任何一項不符就會明確告訴你是哪一項。

所有「可調」的項目都在管理後台 → 系統設定，改完立即生效，不需要重新部署。每間會議室也可以有自己的開放時段，覆寫全域預設值。

覆蓋機制

這是整套系統最需要理解的部分。只有三種可能的結果，而且覆蓋永遠需要你親自按下確認。

三條容易誤解的規則

情況結果原因
等級 5 想覆蓋等級 5不行必須嚴格高於，同級永遠不能互相覆蓋
對方的會議兩小時內就要開始不行已進入保護時間，讓人不會在出門前被抽走會議室
對方的會議已經開始了不行永遠不能覆蓋進行中的會議
覆蓋到自己的另一筆預約不行會提示「您在這個時段已經有預約了」
你被降級後，舊預約被覆蓋會判斷依據是當下的等級，不是訂位當時的等級
被覆蓋的人再去覆蓋更低等級可以連鎖覆蓋是允許的，每一次都會留下紀錄

被覆蓋的人不會知道是誰覆蓋的

通知信只會說明「哪一間會議室、哪個時段被取消了」以及重新預約的連結，不會提到覆蓋者的姓名。這是刻意的設計，避免在同事之間造成不必要的摩擦。系統不會自動幫被覆蓋的人另外安排時段，需要自行重新預約。

為什麼是整筆取消

只要有任何一分鐘重疊，被覆蓋的那筆預約就整筆取消，不會被切成兩半。

每天 280 封的安全上限

免費方案每天可寄 300 封，系統設在 280 封就開始節流。達到上限時優先停掉會議提醒信；驗證信、邀請信、密碼重設信、以及「你的預約被取消了」這類信件永遠照常寄出，因為漏掉它們會讓人被鎖在系統外或錯過重要變動。

管理後台

  • 首頁：待審核人數、今日寄信量與上限、提醒信最後執行時間、近期寄信失敗
  • 審核佇列：姓名、部門、電話、信箱、申請時間，可核准或拒絕
  • 成員管理：搜尋、依狀態與等級篩選、調整等級、停權與復權、刪除帳號（會先跳出確認頁）
  • 邀請管理：批次發送、查看未使用的邀請、撤銷
  • 會議室：新增、編輯、停用與啟用（停用時會先問你要不要一併取消既有預約）
  • 所有預約：依會議室、成員、日期篩選，可代為取消
  • 覆蓋紀錄：誰覆蓋了誰、時間、雙方當時的等級
  • 系統設定：所有規則參數，每一項都附中文說明
  • 寄信紀錄與操作稽核：可匯出 CSV

稽核紀錄永久保留

覆蓋事件、等級調整、審核與拒絕、管理員代為取消、會議室停用，全部永久保留並可匯出，方便日後追查「這個時段當初是怎麼沒的」。

已知限制

  • 首次開啟較慢：免費主機閒置 15 分鐘後休眠，喚醒約需 1 分鐘。
  • 提醒信排程可能被停用：儲存庫連續 60 天沒有動作時，GitHub 會自動停用排程。管理後台首頁會顯示最後執行時間，發現停住就回去重新啟用。
  • 排程可能延遲：GitHub 忙碌時排程會晚幾分鐘，提醒信仍會寄出，只是時間不會分秒精準。
  • 每天 300 封信的上限：以 200 人、每天約 60 筆預約估算是夠用的，但大量發送邀請時要留意。

這個版本沒有做的功能

行事曆整合（ICS / Google）、週期性重複預約、報到與未到紀錄、與會者邀請、單一登入、自訂網域、英文與繁體中文以外的語言、手機 App、候補名單、被覆蓋後的自動改期建議、單筆預約的簽核流程。
